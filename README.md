# Encrypted Sync for Obsidian — 0.5

与 ObsidianBackupServer 配套的账户制加密同步插件，需要 Obsidian 1.11.4+。

## 使用流程

1. 在插件设置中填写服务器地址，**登录或注册账户**。公网地址必须使用 HTTPS；只有本机测试允许 HTTP。
2. 登录后查看该账户下的远端仓库。尚未注册时点击 **创建仓库**，设置仓库名称和仓库加密密码。
3. 已注册的仓库直接选择 **连接并同步** 或 **仅拉取**，输入仓库加密密码即可，无需手工复制 ID、令牌或根密钥。
4. 其他设备登录同一账户，选择同一远端仓库。

“连接并同步”合并本地和远端文件，差异保留冲突副本；“仅拉取”下载远端文件、保留冲突内容并暂停自动上传，恢复双向同步需开启自动同步开关。连接其他远端会重建本地同步索引，不清空本地文件。

登录密码与仓库加密密码应不同：登录密码通过 HTTPS 发给服务器做身份验证；仓库加密密码不发给服务器。每个远端仓库使用随机根密钥，由仓库加密密码加密后注册到服务器。服务器只保存根密钥密文，不保存明文根密钥。

## 本地凭据保护

本地 `data.json.encryptedCredentials` 只保存 AES-256-GCM 密文、版本、随机盐、nonce 和 PBKDF2 参数；令牌和根密钥字段为空。PBKDF2-HMAC-SHA256 迭代 600,000 次，随机盐 16 字节，nonce 12 字节。解锁密码和运行时派生密钥不落盘，没有内置固定解密密钥。

首次连接默认使用仓库加密密码保护本机凭据；每次启动输入一次即可恢复自动同步。可以独立修改本机解锁密码，这不会修改服务器上的仓库加密密码。运行期间凭据必须在内存中解密才能使用，不能防御已取得进程访问权限的代码。

错误密码、密文损坏不会覆盖旧数据或生成替代根密钥。迁移旧 SecretStorage 时，先加密保存并验证，再清除当前仓库引用的旧条目；切换账户模式时会将旧连接根密钥和令牌保留为加密的 `legacyBackup`，避免失去旧数据的访问能力。清理当前存储不保证擦除系统备份或磁盘旧块。请自行保管仓库加密密码及本机解锁密码。

登录会话有效期 30 天，退出登录会在服务器撤销当前会话。失效后暂停自动同步并提示重新登录。

## 自动同步与冲突

参考官方本地/远端仓库与离线恢复行为：<https://obsidian.md/help/sync/vault-types>。

- 解锁后、恢复联网、返回窗口时立即同步，每 5 秒独立检查远端。
- 本地首次变化后约 1 秒触发，连续输入不会无限延迟。
- 请求超时 30 秒，网络失败按 5、10、20、40、60 秒退避重试。
- 修改冲突保留副本；远端删除和重命名清理使用本地 `.trash`。
- Markdown 写入通过 `Vault.process` 校验最新内容；附件写入前重新检查。
- 插件目录、隐藏文件（如 `.env`、`.git`）、缓存、工作区和回收站不参与同步，支持自定义配置目录。
- 文件内容/路径使用 AES-256-GCM，加密块 ID 使用独立 HMAC。大文件支持分块去重。

当前使用轮询，尚无实时推送、Markdown 三方自动合并、可视化历史恢复、账户密码找回或共享仓库。大型仓库仍会周期性扫描；附件/外部程序同时写入不提供跨进程事务保证。应用关闭或系统休眠时无法执行同步。

## 升级旧版仓库

0.5 服务端不再接受旧全局令牌。旧远端数据不会自动归属首个注册用户，以防止被认领。

登录新账户后，若检测到旧凭据，设置中显示“迁移旧版远端仓库”。使用“导出密钥密文”设置仓库加密密码；这只生成 `legacy-key-envelope.json`，不会修改或删除原密钥。管理员按服务端 README 将旧仓库绑定给账户，之后刷新列表并选择即可继续同步。

## 构建与安装

```sh
npm install
npm run build
```

将 `main.js`、`manifest.json`、`styles.css` 复制到每个本地仓库独立的 `.obsidian/plugins/obsidian-encrypted-sync/` 中。不要让两个仓库共用同一个插件数据目录。

## 测试

```sh
# ObsidianBackupServer
cargo build
cargo test
# ObsidianPlugins
npm test
npm run test:integration
```

集成测试运行真实 Rust 服务，覆盖注册、登录、退出、同名仓库、跨用户隔离、未注册仓库拒绝、首次同步、双端冲突、重命名/重试、删除/重建、附件、空文件、下载期间修改、密文验证和迁移失败。Obsidian API 使用测试适配器。

真实应用测试：开启 Obsidian CLI，执行 `node tests/test-account-live.mjs`。脚本创建 `../AccountSyncTests/AccountTest-A` 与 `AccountTest-B`，在 `127.0.0.1:18788` 启动隔离服务，使用公开的、仅供测试的密码验证账户完整流程，生成 `live-account-report.json`。这些测试凭据不可用于真实账户。已有专用测试目录可用 `--resume` 继续，不覆盖已有笔记。
